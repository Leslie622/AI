## 基础与训练

| 术语 | 一句话定义 |
|---|---|
| 人工智能 AI | 让机器表现出智能行为的总称 |
| 机器学习 ML | 从数据中学规律，而不是手写规则的 AI 子领域 |
| 深度学习 DL | 用多层神经网络自动学习特征的 ML 分支 |
| 神经网络 | 由大量简单计算单元加权连接组成的可学习函数 |
| 参数 / 权重 | 网络中可学习的数字，"模型的知识"就存在这里 |
| 训练 | 用数据 + 梯度下降调整参数的过程 |
| 推理 | 训练好的模型对新输入给出输出的过程（LLM 应用时代你 99% 时间在用这个） |
| 预训练 | 在海量文本上做"下一词预测"，产出基座模型 |
| 后训练 | 用 SFT / RLHF 把"补全机器"调成"听指令的助手" |
| SFT | 监督微调：用高质量问答对教模型行为 |
| RLHF | 用人类偏好信号做强化学习，对齐模型输出 |
| 微调 / LoRA | 在已有模型上小幅定制；LoRA 是低秩高效微调法 |
| 开源模型 | 权重公开可下载的模型（Llama、Qwen、DeepSeek 等） |
| 本地模型 | 跑在自己电脑上的开源模型（Ollama / LM Studio） |

## 模型行为

| 术语 | 一句话定义 |
|---|---|
| Transformer | 当代 LLM 的骨干网络架构（2017 年《Attention Is All You Need》） |
| 注意力 Attention | 每个词对其他所有词加权"关注"的机制，Transformer 的核心 |
| Token | 模型处理文本的最小单位（1 token ≈ 0.75 个英文单词 ≈ 0.5 个汉字），计费与上下文长度的单位 |
| Embedding | 把文本映射成向量，语义越近向量越近，是语义检索的基石 |
| 上下文窗口 | 模型一次能"看到"的最大 token 数，即工作记忆的容量 |
| 温度 temperature | 采样随机度：低→稳定精确，高→多样发散 |
| top_p | 另一种采样控制：只在累计概率前 p 的候选词里选 |
| 幻觉 | 模型一本正经编造事实的现象——它本质是在"续写"而不是"查资料" |
| 知识截止 | 训练数据的最后日期，之后发生的事模型不知道 |
| 推理模型 | 先生成"思考过程"再作答的模型（OpenAI o 系列、DeepSeek-R1 类），用推理时间换答案质量 |
| 多模态 | 能同时理解文字、图像、音频等多种输入的模型 |

## 对话控制

| 术语 | 一句话定义 |
|---|---|
| System Prompt | 设定模型角色与规则的最高优先级指令 |
| Prompt 工程 | 通过指令、示例、结构设计来稳定获得想要输出 |
| Few-shot | 在 prompt 里给几个输入输出示例，教会任务模式 |
| 思维链 CoT | 让模型先写推理步骤再给答案 |
| 结构化输出 | 强制模型按 JSON Schema 输出，应用可靠消费模型结果的生命线 |
| Function Calling | 模型按 schema 返回"我想调用某函数"，由你的代码执行后把结果喂回 |
| 上下文工程 | 系统化设计每次请求携带的全部信息（系统指令 + 检索内容 + 历史 + 工具），Prompt 工程的进化版 |
| 流式输出 | SSE 逐 token 返回，打字机效果的来源 |
| 提示注入 | 用恶意输入劫持模型指令的攻击——用户输入永远不可信 |

## 检索与知识

| 术语 | 一句话定义 |
|---|---|
| RAG | 检索增强生成：先查资料，把资料放进上下文，再让模型回答 |
| Chunking | 把长文档切成适合检索的小块 |
| 向量库 | 存储 embedding 并支持相似度检索的数据库 |
| 混合检索 | 关键词（BM25）+ 向量两种检索并用，互补短板 |
| 重排 Rerank | 用更精细的模型对初筛结果做二次排序 |

## Agent

| 术语 | 一句话定义 |
|---|---|
| Workflow vs Agent | 工作流 = 人写死代码路径；Agent = 模型自己决定路径（Anthropic 定义） |
| Agent Loop | "思考 → 调工具 → 看结果 → 再思考"的循环，Agent 的心脏 |
| ReAct | Reasoning + Acting 交替进行的经典 agent 范式（2022 论文） |
| 工具 Tool | 暴露给模型的能力（函数/API），工具描述就是给模型看的接口文档 |
| 规划 Planning | 把大任务分解成可执行步骤，再逐步执行 |
| 记忆 Memory | 短期 = 上下文的裁剪与压缩；长期 = 外部持久化存储 |
| 多智能体 | 多个 agent 分工协作，典型如"编排者-工作者"模式 |
| Handoff | 一个 agent 把任务连同上下文移交给另一个 agent |
| MCP | Model Context Protocol，工具与数据接入的开放标准——"AI 的 USB-C" |
| 护栏 Guardrail | 限制模型输入输出的安全机制 |
| 人在环 HITL | 关键动作执行前必须有人类确认 |
| Evals | 对模型/应用的系统化评测：评测集 + 评分标准 + 回归测试 |
| LLM-as-judge | 用另一个模型（或同款模型）按标准给输出打分 |
| Tracing | 记录一次请求的完整轨迹（每次调用、工具、耗时），调试 Agent 的显微镜 |

## 工程化

| 术语 | 一句话定义 |
|---|---|
| OpenAI 兼容协议 | 事实上的统一 API 形态，换模型只改 base_url 和 key |
| 模型网关 | 统一代理多家模型 API 的中间层（路由、计费、限流） |
| 速率限制 | API 对请求频率与用量的限制（RPM / TPM） |
| 成本工程 | 缓存、小模型路由、上下文瘦身等省钱手段 |
| 可观测性 | Tracing + 日志 + 指标，让 LLM 应用可调试 |
| Tokenizer Playground | 可视化文本如何被切成 token 的小工具 |
