Python 策略：能读 + AI 写 + 人审，不系统学

验收：能用一句话说清你的 Python 策略；拿到一段教程代码，知道怎么读懂它、怎么审它。

为什么绕不开，又不用系统学？

AI 世界的母语是 Python：教程、论文配套代码、HuggingFace 的 demo、RAG 工具链（很多框架 Python 版先发）全是它。绕不开。

5 个"第一次见会愣住"的语法点

  1. 缩进即语法——不是风格问题，是语义。从网页复制的代码先检查缩进；混用 tab 和空格直接 IndentationError。
  2. 可变默认参数坑——def add(item, acc=[]) 里的默认列表只在函数定义时创建一次，之后所有调用共享同一个列表！审代码必查项。
  3. 列表推导式——读法："对 xs 里每个满足条件的 x，收集 f(x)"。[x.name for x in users if x.active] ≈ users.filter(u => u.active).map(u => u.name)。
  4. *args, **kwargs 与 ** 解包——函数定义处的 **kwargs 收集关键字参数；调用处的 f(**config) 把 dict 摊开成参数。类比 f(...arr) 和 {...obj}。
  5. 装饰器 @xxx——函数头顶的 @ 行，是高阶函数包装：自动加缓存、重试、注册路由等。类比 React 高阶组件 / Express 中间件。看到 @app.get("/api") 就是"把这个函数注册成路由"。

支柱三：人审 —— Python 特有审查点

在 1.5 的通用清单之上，叠加这些 Python 专属项：

工具链最小集：uv（README 指定）

uv 是 2024 年后 Python 社区的新默认工具（Rust 写的，极快），一个命令搞定 venv + 依赖 + 运行。Git Bash 下的最小工作流：

uv venv                            # 创建 .venv（传统等价：python -m venv .venv）
source .venv/Scripts/activate      # 激活（Windows 是 Scripts/，不是 Linux 的 bin/）
uv pip install requests            # 装依赖（等价 pip install，但快得多）
uv run main.py                     # 用 .venv 环境跑脚本（不激活也行）
deactivate                         # 退出虚拟环境
⚠️ Windows 三个小坑① 终端里 python 可能指向 Microsoft Store 的占位符——用 py -3 或让 uv 管理；② 激活脚本在 .venv/Scripts/（不是 Linux 的 bin/）；③ 装包慢或失败时，给 pip/uv 配国内镜像（如 https://pypi.tuna.tsinghua.edu.cn/simple）。

2.3

HTTP · JSON · 开发环境 —— 查漏即可

验收：能讲明白"打字机效果"的原理；环境清单全绿。

HTTP 基础、JSON 序列化、Node、Git、VS Code——你有 TS 工程底子，这些都已具备，不赘述。本节只讲 LLM 场景下的三个增量知识点。

增量一：SSE —— 打字机效果的原理（本章最重要新知识）

普通 HTTP 是"请求 → 干等 → 完整响应"。而 LLM 生成一篇文章要十几秒，让人干等体验就完了，所以要边生成边推送。主流方案是 SSE（Server-Sent Events）：

  • 本质还是一个普通 HTTP 响应，只是不一次写完——服务器持续往连接里写小块，写完才关。
  • 格式：响应头 Content-Type: text/event-stream，正文是一行行 data: {...}（每条后跟空行），OpenAI 兼容协议以 data: [DONE] 结尾。
  • 每个 data: 里就是一个 JSON：本次新增的几个字 + 计数。前端逐条解析、追加渲染，就是你看到的"打字机"。
⚠️ 前端老认知的一个坑你可能认识 EventSource API——但它只支持 GET、不能带 Authorization 头，而 LLM API 全是 POST + 鉴权头。所以实战里不用 EventSource，而是 fetch + ReadableStream 手动解析，或者干脆用 SDK（它帮你封装好了）。第 6.2 章会亲手写一遍。

SSE vs WebSocket：SSE 单向（只服务器→客户端）、纯 HTTP、自带重连，聊天流式输出足够了；WebSocket 双向、独立协议，实时语音对话那种场景才需要。为什么不用 WebSocket 做聊天？杀鸡用牛刀，还多一个协议升级。

增量二：JSON 的两个变体

  • JSON Schema——描述"JSON 该长什么样"的类型定义。LLM 结构化输出（5.3）的合同：你给 schema，模型照着生成。你在 TS 里用的 Zod 就是它的近亲——AI SDK 允许直接用 Zod 定义、自动转换（6.3 会用到）。
  • JSONL（JSON Lines）——每行一个独立 JSON 对象。训练数据和日志的常见格式，好处是可以逐行流式读取，不必把整个文件载入内存。

增量三：环境查漏清单

🇨🇳 国内开发者的真实第一坑：网络可达性直连 OpenAI / Anthropic / Google 的 API 通常需要代理，且代理不稳定会直接变成应用事故。务实策略：起步用国内可直连、OpenAI 兼容的 API（DeepSeek / 智谱 GLM / 硅基流动），课程推进不受网络摆布；想体验海外旗舰时再走稳定通道或聚合网关（OpenRouter）。这个选择不影响学习效果——协议是同一套。

Step 2 · first-call.ts（约 20 行，逐段讲解）

新建目录，初始化，装两个开发依赖：

npm init -y && npm i -D tsx dotenv

项目根目录建 .env（记得加进 .gitignore！）：

LLM_API_KEY=sk-xxxxxxxx

然后写 first-call.ts：

import "dotenv/config";

const BASE_URL = "https://api.deepseek.com"; // 换厂商只改这里 + model 名

const res = await fetch(`${BASE_URL}/chat/completions`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${process.env.LLM_API_KEY}`,
  },
  body: JSON.stringify({
    model: "deepseek-chat",
    messages: [
      { role: "system", content: "你是一个文言文翻译官，只输出译文。" },
      { role: "user", content: "翻译：我从今天开始系统学习 AI 了。" },
    ],
    temperature: 1.2,
    max_tokens: 200,
  }),
});

const data = await res.json();
console.log(data.choices[0].message.content); // 模型回复
console.log(data.usage);                       // token 用量，4.7 章的主角

运行：npx tsx first-call.ts。逐段认识这份"行业通用合同"：

  • messages——对话的核心结构。system 定角色（幕后指令），user 是用户输入，还有第三种 assistant（模型自己的历史回复，多轮对话靠它实现"记忆"）。5.1 章主角。
  • temperature——随机度旋钮。0 = 每次选概率最高的词，稳定但呆板；越高越随机越有创意。4.6 章主角。
  • max_tokens——回复长度上限，也是成本上限（计费按 token）。4.7 章主角。
  • choices[0].message——回复本体；usage——这次花了多少 token（提示/生成/总量）。做成本控制时天天看它。

Q1（2.1）一句话说清你的 Python 策略；随口说出 5 组 TS↔Python 对应
策略："Python 是阅读语言+脚本工具——能读（TS 类比）、AI 写、我人审，不系统学。"对应物举例（任答 5 组）：venv≈node_modules、pip≈npm、f-string≈模板字符串、列表推导≈map+filter、async/await 几乎一样、pyproject.toml≈package.json、__init__.py≈index.ts。
Q2（2.1）可变默认参数的坑是什么？为什么 is 不是 ===？
坑：默认参数（如 def f(acc=[])）在函数定义时只创建一次，之后所有调用共享同一个列表/字典——状态会跨调用泄漏，应默认用 None 再在函数体内新建。is 判断的是"是否同一个对象"（引用/身份），== 才是值相等；它俩的关系不对应 JS 的 ===/==。
Q3（2.2）线代 / 概率 / 微积分各对应课程哪一站？
线代 → Embedding 与向量检索（4.2 / 7.3）；概率 → 解码采样、温度/top_p（4.6）；微积分 → 梯度下降一句话直觉（3.2，之后再不出现）。
Q4（2.3）给同事讲明白：打字机效果怎么来的？EventSource 为什么不能直接调 LLM API？
LLM 逐 token 生成，服务端用 SSE（还是普通 HTTP 响应，只是边生成边写）持续推送 data: {...} 小块，前端逐条解析追加渲染。EventSource 只支持 GET 且不能带 Authorization 头，而 LLM API 是 POST + 鉴权，所以要用 fetch + ReadableStream 或 SDK 封装。
