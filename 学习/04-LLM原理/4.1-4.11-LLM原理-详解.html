4.1

Token 与 tokenizer

验收：知道模型的"字"是什么、怎么数、怎么换算成钱。

Token = 模型处理文本的最小单位。在模型的世界里没有"汉字"、没有"单词"，只有 token ID（一个数字）——文本先进分词器（tokenizer）切成 token、映射成数字序列，模型才有东西可处理；输出也是反过来把 token ID 还原成文字。你在控制台里填的 max_tokens、日志里的 prompt_tokens，数的就是它。

BPE 分词直觉【了】（知道思路即可）

为什么不按字或按词切？按字切序列太长、语义太碎；按词切词表会爆炸、遇到新词（"赛博朋克化"）就没辙。主流方案 BPE 的思路是折中：从海量语料里统计"哪两个相邻单位经常一起出现"，反复合并高频组合——于是"的""了""the""ing"这类高频单位各自一个 token，生僻词被拆成几个碎块。词表是"用出来的"，不是人编的。

换算手感（粗略，分词器而异）

内容大致换算备注

4.2

Embedding 与语义向量

验收：能说出"embedding 是什么、语义相似度怎么来的"，并亲手算出三对句子的相似度。

Embedding = 把一段文本映射成一串数字（向量，通常上千维）。关键性质：语义相近的文本，向量在空间里挨得近。"前端开发"和"写 CSS"会被映射到相邻位置，和"红烧肉的做法"隔得很远——哪怕前者之间没有共同词汇。这是模型在海量文本上学到的"语义地图"。

语义空间示意：同话题的句子聚成一簇。"相似度"= 两个点的距离（常用余弦相似度：夹角越小越相似，1 = 同向，0 = 无关）。

为什么这个概念至关重要

  • LLM 内部的一切都发生在向量空间——每个 token 进入模型后都会被表示成向量，注意力（4.3）做的全都是向量之间的运算。
  • 它是 RAG 的地基（第 7 章）：把文档切成块、全部 embedding 入库；用户提问也 embedding，找"离得最近的几块"喂给模型——语义搜索。注意它不是字符串匹配："怎么部署模型"能搜到"如何上线模型"，搜不到"红烧肉"。
  • 经典彩蛋（提一句就好）：向量空间里方向也有语义，"国王 − 男人 + 女人 ≈ 女王"。
🔧 动手 4.2（README 指定）用 TS 调 embedding API，算三对句子的相似度。
  • 注意：DeepSeek 没有公开 embedding 接口，需要另一个支持 embedding 的服务——推荐硅基流动（免费额度，模型 BAAI/bge-m3，OpenAI 兼容协议）；或智谱 GLM 的 embedding 模型
  • 新建 实验/first-call/embedding-sim.ts（复用该目录的依赖，npx tsx embedding-sim.ts 运行）：
import "dotenv/config";
// .env 里加：EMBED_BASE_URL=https://api.siliconflow.cn/v1
//            EMBED_API_KEY=你的硅基流动Key（或临时用 LLM_API_KEY 旁路传入）
const BASE = process.env.EMBED_BASE_URL!;
const MODEL = process.env.EMBED_MODEL ?? "BAAI/bge-m3";
const texts = ["前端开发", "写 CSS 样式", "红烧肉的做法"];

const res = await fetch(`${BASE}/embeddings`, {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${process.env.EMBED_API_KEY}` },
  body: JSON.stringify({ model: MODEL, input: texts }),
});
const data: any = await res.json();
const vecs: number[][] = data.data.map((d: any) => d.embedding);

const dot = (a: number[], b: number[]) => a.reduce((s, x, i) => s + x * b[i], 0);
const norm = (a: number[]) => Math.sqrt(dot(a, a));
const cosine = (a: number[], b: number[]) => dot(a, b) / (norm(a) * norm(b));

console.log(`维度: ${vecs[0].length}`);
for (let i = 0; i < texts.length; i++)
  for (let j = i + 1; j < texts.length; j++)
    console.log(`"${texts[i]}" vs "${texts[j]}" → ${cosine(vecs[i], vecs[j]).toFixed(3)}`);
  • 预期观察："前端开发"vs"写 CSS"相似度明显高（0.5+），"红烧肉"那对明显低（0.3 以下）——语义相似度第一次在你手里变成数字。需要我帮你把这个脚本挂进实验工程跑通的话，说一声即可

4.3

Transformer 与注意力（直觉层）

验收：只求看懂一张图——"每个词看所有词并加权关注"（README 原话）。不要求复述矩阵运算。

1.2 里说过：2017 年的 Transformer 是所有现代 LLM 的共同祖先，核心创新是注意力机制。它解决的问题很具体：

"小明把书借给了小红，因为它快看完了。"——"它"指的是书还是小明？

人类靠语境秒懂。注意力机制让模型在处理每个词时，回看句中所有词，按"相关性"给每个词分配关注度权重，把相关的信息加权吸收进来——"它"会强烈关注"书"（快看完了的是书），于是向量里就带上了"指代书"的信息。

处理"它"时，注意力把大部分权重给了"书"——指代消解就这样发生。每个词、每一层都在做同样的事。

三个"知道名字即可"的零件

  • Q / K / V（查询·键·值）：注意力内部分工的三份向量。类比：每个词举着一张名片（Key，"我是什么"）、手里一个资料袋（Value，"我携带的信息"），正在处理的词拿着一张需求单（Query，"我在找什么"）——需求单和名片逐个比对，匹配度高的资料袋被重点吸收。
  • 位置编码：注意力本身不分先后（"你借我书"和"我借你书"看起来一样），所以要额外给每个词注入"我排第几"的信息。
  • 多头注意力：同一句话并行做多套注意力——有的头盯指代、有的盯语法、有的盯语义（名字知道即可）。

为什么这个设计赢了这个时代

  • 长距离依赖直接连通：任意两个词一步可达，隔 500 字的指代也能被"看到"（旧架构只能逐词传递，距离一远信息就稀释）。
  • 训练完全并行：句子里所有位置可以同时算，不吃"上一个词必须先算完"的串行限制——这是 1.2 说"规模化从此可行"的技术根源。
学习姿势本章对 Transformer 的要求就到这：看懂上面那张图，能对别人说"每个词看所有词、按相关性加权吸收"。想加深直觉：3Blue1Brown attention 特别篇⭐（第 4 章资源里唯一强烈推荐的视频）；图文版看 The Illustrated Transformer（只看图）。矩阵运算一律跳过。
🧠 记忆钩子注意力 = 全局加权关注。Transformer 的两个超能力：长距离直接连线 + 训练并行。这两个超能力分别兑换成"能力"和"规模"（4.4）。
4.4

预训练：下一词预测 · Scaling Law 【浅】

验收：能回答"预测下一个词这么简单的任务，凭什么学出智能？"和"Scaling Law 是什么"。回收第 3 章词汇。

任务：预测下一个词

预训练的任务简单到不像真事：给模型看海量文本，每次遮住下一个词让它猜，猜错算损失（3.2），梯度下降调参数，重复几万亿次。这就是 3.1 说的自监督——答案从文本里免费自造，所以能吃下几乎整个互联网。

凭什么"猜词"能猜出智能？

因为要把下一个词猜对，就必须先理解上下文："戴上安全___"要猜对"帽"，得懂物理常识；"37 × 24 = ___"要猜对，得会算术；"她津了津嘴，因为咖啡太苦，一定是忘了放___"要猜对，得懂因果和糖。语法、事实、推理，都是"把下一词猜准"的副产品。有一句业界名言概括它：压缩即智能——把海量文本压进有限参数还都能接得上，唯一办法是真正学到里面的规律。

Scaling Law：砸规模，能力可预测地涨

2020 年前后的重要发现：模型能力随"参数量 × 数据量 × 算力"三个因素的增大，按可预测的曲线上升，且截至目前未见天花板。这就是 1.2 里第一条规模化曲线，也是整个 2020s 军备竞赛的理论执照——既然"更大=更强"是定律，那就值得砸钱。2024 年 o1 发现的第二条曲线（推理时算力，4.9）是对它的补充而非替代。

预训练的产物：一台"补全机器"

注意：预训练刚结束的模型（base model）只会续写，不会对话——你问"法国首都是哪"，它可能接着写"这道题是小学地理常考题，答案我们下节课讲"，因为它见过的语料里这句话后面就是这么接的。它渊博但油盐不进。把它调教成助手，靠的是——

🧠 记忆钩子预训练 = 在整个互联网上做下一词预测；智能是"猜准"的副产品（压缩即智能）；Scaling Law = 砸规模买能力；产物是一台渊博但不听指令的补全机器。

后训练：SFT / RLHF / DPO 【浅】

验收：能讲清"从补全机器到助手"的三步调教，各步骤一句话。
步骤怎么做解决什么回收哪节
① SFT
监督微调		人类写几万~几十万条高质量"问题 + 理想回答"，做监督学习继续调参数教会它"对话的基本礼仪"：一问一答、听指令、有用格式3.1 监督学习

③ DPO
直接偏好优化		近年新方法：跳过奖励模型，直接从"偏好对"（好回答/坏回答）学习效果近似 RLHF，工程更简单稳定——很多新一代模型用它——

三步走完，"补全机器"才变成你熟悉的助手：助手的人格、礼貌、拒答边界、"作为一个 AI 我不能……"，全是这个阶段塑造的。你在控制台里体验到的所有"听话"，都是后训练的功劳；而 system prompt 能有效指挥它，也是因为它被训练成了"听指挥的助手"。

顺带一提：你上一章看到的"推理模型训练"（R1-Zero 那类纯强化学习）是后训练阶段的最新分支——用 RL 不教"回答更好"，而教"思考更好"（4.9）。

🧠 记忆钩子预训练给知识（渊博），后训练给人格（听话）。SFT 教礼仪 → RLHF 教偏好 → 模型出厂。
4.6

解码与采样：温度 / top_p

验收：说清温度和 top_p 各控制什么；亲手完成 0 / 0.7 / 1.5 × 5 次的对照实验并记录（README 指定）。

模型每一步给出的不是"答案"，是"概率表"

生成每个 token 时，模型输出的其实是整张词表上"下一个是谁"的概率分布（如"帽"62%、"围巾"18%、"手套"9%、其余分摊）。解码策略决定怎么从这张表里挑。你调的 temperature 就是拨这张表形状的旋钮：

同一个上下文，温度不同，"下一个词"的概率表形状完全不同。T=0 时等价于"永远取第一名"（贪心），输出确定。
  • 温度（temperature）：调分布的尖锐/平坦。→0 = 贪心，同样输入永远同样输出（确定性）；→高 = 平坦，冷门词机会大增（多样但也容易胡言，你实验里 1.5 的"胡言乱语"就是它）。
  • top_p（核采样）：另一个旋钮——只从"累计概率排前 p"的候选里抽（如 top_p=0.9 即"只从贡献了前 90% 概率的小圈子"里抽），候选池随语境动态伸缩。与温度通常二选一调，别同时乱动。
  • top_k：top_p 的固定版——永远只从概率前 k 名里抽（一句话知道即可）。
⚠️ 实验前注意做对照实验请把 model 切到 deepseek-chat（非思考模式）——推理模型（你正在用的 deepseek-flash）对温度不敏感甚至忽略它，实验结果会不干净。这本身也是 4.9 的一个实践知识点。

4.7

上下文窗口与成本

验收（README 原题）：为什么长对话越聊越贵？上下文窗口和"记忆"是什么关系？

窗口 = 模型一次能"摊开"的工作台

上下文窗口是单次调用里模型能处理的 token 上限，输入和输出一起算（输入 30K + 输出 2K = 占用 32K 窗口）。2026 年旗舰在 128K~1M+ 量级（1M ≈ 约 150 万汉字，约等于把一套《三体》塞进去一次读完）。超出就报错或被截断——所以超长文档要分段（第 7 章）。

"记忆"的真相：无记忆，只有重发

模型没有记忆。你感觉"它记得我们刚才说的话"，是因为每次调用都把全部历史重新发送——第 2 章观察表第二组实验你已经亲手做过（把 assistant 回复塞回 messages，它就"记得"了）。两个推论：

  • 不存在"遗忘"，只存在"装不下"（超窗口）和"顾不上"——提到后者：研究表明模型对超长上下文中段的信息利用较弱（lost in the middle，5.5 讲），"在窗口里"不等于"一定被用好"。
  • "越聊越聪明"的错觉同源（3.3）：它不是学到了什么，是你喂的上下文变多了。

为什么长对话越聊越贵（验收题一）

因为历史全量重发。假设每轮你们各说 500 token：

轮次实际发送的输入按输入单价付费的量
第 1 轮500500
第 5 轮5 × 10005,000
第 20 轮20 × 100020,000（成本线性膨胀）

第 N 轮的费用 ≈ 历史总 token × 输入单价，线性增长。这就是 8.5「记忆管理」（截断/压缩历史）和 5.5「上下文工程」存在的经济动机——长对话不是无限聊下去，而是要有人负责"打扫工作台"。

缓存：同样前缀的第二遍很便宜

你日志里见过 cached_tokens：请求的前缀部分（固定的 system prompt + 相同的历史开头）如果和之前的请求一致，厂商可以复用之前的计算结果，命中部分按约 1/10 甚至更低计费。两个实践推论：① system prompt 尽量固定写在开头、别每次变；② 多轮对话天然命中缓存——这也是"长对话没有想象中贵"的一道缓冲（但只缓冲前缀，新增部分照常收费）。

🔧 动手 4.7（选做）在控制台用完全相同的请求（同 system、同 user、同参数）连发两次，对比两次日志里的 cached_tokens——第二次应出现命中。顺便体会"前缀一致"是缓存生效的前提。
🧠 验收题答案① 越聊越贵：历史每轮全量重发，费用随历史长度线性增长（缓存只减免不变的前缀）。② 窗口和记忆：窗口 = 单次调用的最大工作台；"记忆"是错觉，本质是每轮把历史重新喂一遍——装不下就真的忘了，且中段内容容易被"看见但没用好"。
4.8

幻觉与知识截止

验收（README 原题）：为什么幻觉必然存在？什么时候危险？

知识截止：模型有"出生日期"

模型的知识 = 预训练数据的快照，数据有截止日期，之后的世界变化它一概不知（除非你告诉它或它去联网查）。这不是 bug，是训练机制的必然——参数在训练结束时冻结（3.3）。对策是第 7 章的 RAG 和工具联网：把新知识"喂"进上下文，而不是指望模型"知道"。

幻觉：为什么必然存在（验收题一）

回到 4.4 的本质：模型是概率续写器，不是事实查询库。它生成每个 token 的优化目标始终是"下一个最像的词"，而"像真的"和"是真的"是两件事。当它遇到训练数据里没覆盖的具体问题，它不会"宕机"，而是照样按概率续写出一个语法通顺、语气自信、细节俱全的编造——这就是幻觉。

  • 为什么"必然"：生成机制决定了它永远能编造合理内容；后训练只能教它"多承认不知道"（4.5），无法内置一个可靠的"我此刻在编造"探测器。幻觉无法根除，只能缓解和兜底。
  • 你已见过的实例：1.5 里"编造 npm 包名"（甚至被供应链攻击利用）、4.4 里 base model 一本正经地续写跑题内容。

什么时候最危险（验收题二）

  • 越具体越危险：数字、日期、人名、法条、药名、文献引用、API 参数——这类内容编造率高，且编出来"形状完美"最像真的。
  • 无验证渠道时：用户无法当场核实（医疗、法律、金融建议），或自动化流水线里没人看（Agent 自动执行，8.14 安全）。
  • 反直觉的一条：降低温度不解决幻觉——低温只是让它稳定地、重复地编同一个故事（4.6 的经验法则里"低温=稳"是"稳定"，不是"正确"）。

缓解工具箱（后续章节逐一解锁）

  • RAG：只让它基于检索到的资料回答（7 章）——主力手段
  • 联网/工具调用：让模型查了再答（5.4、8 章）
  • Prompt 要求引用来源 + 人工抽查（5 章）
  • 结构性兜底：关键决策不交给模型单方定断（8.15 人在环）
🧠 验收题答案① 必然存在：它是概率续写器，"像真的"≠"是真的"，机制上无法内置"我在编造"探测器，只能缓解。② 最危险：具体事实类内容 + 用户无验证渠道 / 无人看管的自动化场景。
4.9

推理模型（思考 token）

验收：贵在哪、什么场景值得用——你已经在控制台里付出过"学费"了（200 token 全花在思考上那次）。

机制：把"思考"也变成普通 token

推理模型（o1 / R1 / 你在用的 deepseek-flash 等）的做法：用强化学习训练模型"回答前先生成一段思考"——拆解问题、尝试方案、自我检查——然后把正式回答写出来。关键认知：

  • 思考 token 和答案 token 是同一种东西（同一条生成流水线），只是被放进 reasoning_content 字段单独展示——你亲眼见过内容被截断成空的案例。
  • 思考照常占用 max_tokens、照常计费（usage 里的 reasoning_tokens）。
  • 本质是 1.2 的第二条规模化曲线：推理时算力换能力——训练规模之外，"让它多想一会儿"也能买准确率。

贵在哪、什么值得（验收题）

维度普通模型推理模型
响应速度秒级直出先思考几秒~几十秒再答
成本答案 token 计费思考 token 也在计费（常常比答案还多）
擅长翻译/分类/格式转换/简单问答数学、复杂代码、多步规划、难题拆解
温度灵敏可调（4.6）通常忽略或限制温度

判断口诀：任务需要的"想"，超过它需要"写"，才用推理模型。让推理模型翻译一句话 = 请数学教授帮你抄电话号码（你已实证）。第 6.6 会给完整的选型决策表。

🔧 动手 4.9你已经完成了大半：① 那次"content 为空"的调用（思考耗尽预算）；② 把 model 在 deepseek-chat / deepseek-flash 之间切换的对比。补最后一步：同一个需要推理的题（如"9.11 和 9.9 哪个大？为什么？"）分别用两个模型跑，对比正确率与耗时——这就是"何时值得"的体感。
🧠 记忆钩子思考 = 普通 token 的特权化展示：占预算、要计费、能换准确率。贵在"想"，值在"难"。
4.10

效率概念 【浅】：MoE / 量化 / 蒸馏 / KV 缓存

验收：每个一句话说清（大纲要求）。你在日志和新闻里其实都见过它们。
技术一句话你在哪见过它
MoE
混合专家		模型内部有众多"专家"子网络，每个 token 只激活其中一小部分——总参数万亿级，单次计算量却像百亿级DeepSeek / Qwen 旗舰全是 MoE；1.2 里"万亿参数时代"的前提技术
量化把权重的数字精度调低（FP16 → INT4），体积缩几倍、速度更快、精度略损第 9 章 Ollama 本地跑模型的唯一途径——消费级显存装得下的秘密
蒸馏大模型当老师教小模型，小模型以极小成本逼近大模型部分能力各家"mini / flash / lite"型号的来源；端侧 AI 的前提
KV 缓存生成第 N 个词时不重算前 N−1 个词的中间结果，缓存下来复用——流式输出越写越顺的幕后功臣你在控制台看到的流畅打字机效果；4.7 的前缀缓存（cached_tokens）是它经济化的应用
🧠 记忆钩子四个词都是"省"字诀：MoE 省计算（少激活）、量化省显存（降精度）、蒸馏省参数（换老师）、KV 缓存省重复（不重算）。
4.11

多模态 【浅】：图 / 音频怎么"进"模型

验收：一句话说清多模态的实现思路。

核心思想一句话：万物皆 token。图像被切成小块（patch，类似 ViT 做法）各自变成 token；音频被切成帧并离散化成 token；文字本来就 是 token——然后全部塞进同一个 Transformer，用同一套注意力机制互相参考。

  • 所以"多模态"不是"外挂几个工具"，而是同一个人脑结构里装了多种感官——GPT-4o 能"边看边说"，正因为图和音在它内部已经是统一的 token 流。
  • 这也解释了 3.5 说的"领域合流"：一旦万物皆 token，模态边界就只剩"tokenizer 不同"。
  • 成本直觉：图像按分辨率折算成 token 计费（一张图几百~几千 token），所以"发图"并不免费。
🧠 记忆钩子多模态 = 万物皆 token，同一个 Transformer 全包。

Q1（4.1）为什么模型用 token 不用字/词？中文大概怎么换算？
按字太碎序列长、按词表爆炸且无法处理新词；BPE 用数据统计折中（高频组合合并成 token）。中文常用字约 0.6~1.5 token/字（分词器而异），代码 JSON 效率最低。
Q2（4.2）Embedding 是什么？为什么"怎么部署模型"能搜到"如何上线模型"？
文本映射成上千维向量，语义相近则距离近。搜索是找向量近邻（语义匹配），不是字符串匹配——同义不同词也能命中。你亲手算过三对句子的余弦相似度。
Q3（4.3）注意力机制一句话？它带来哪两个超能力？
每个词看所有词、按相关性加权吸收信息（"它"→重点看"书"）。超能力：① 任意两词直接连通（长距离依赖）② 全位置并行计算（训练可规模化）。
Q4（4.4/4.5）为什么猜词能猜出智能？base model 和助手差在哪？
猜准下一词必须先理解语境——语法/事实/推理是副产品（压缩即智能）。base model 只会续写（渊博但不听指令）；经 SFT 教礼仪 + RLHF/DPO 教偏好，才变成助手。
Q5（4.6）温度和 top_p 各控制什么？T=0 输出确定，为什么不等于更正确？
温度调概率表尖锐/平坦（0=贪心，每次一样）；top_p 限制只在累计概率前 p 的候选里抽。低温=稳定重复，不=正确——幻觉照旧（4.8），别拿低温当解药。
Q6（4.7）为什么长对话越聊越贵？"它记得我们说过的话"的机制是什么？
每轮把全部历史重发，费用随历史线性增长（前缀缓存只减免不变部分）。"记忆"= 每轮重发历史的错觉；窗口=单次工作台上限，装不下就真忘。
Q7（4.8）为什么幻觉必然存在？最危险的场景？
模型是概率续写器，优化"像真的"而非"是真的"，机制上没有可靠的"我在编造"探测器。最危险：具体事实（数字/引用/API）+ 无验证渠道/无人看管的自动化。
Q8（4.9）推理模型的"思考"和普通生成有什么区别？什么时候值得用？
没本质区别——思考也是普通 token，只是放进 reasoning_content；占 max_tokens、照常计费（reasoning_tokens）。值得用：任务"需要想的"超过"需要写的"（数学/规划/难题）；翻译抄写类是浪费。
Q9（4.10/4.11）MoE / 量化 / 蒸馏 / KV 缓存各一句话？多模态的核心思想？
MoE 省计算（每 token 只激活部分专家）；量化省显存（降数字精度）；蒸馏省参数（大教小）；KV 缓存省重复（已生成部分不重算）。多模态：万物皆 token，图/音频切块离散化后进同一个 Transformer。
